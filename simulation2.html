What is the thing on your network — and how sure can you be?

Discovery (Simulation 1) tells you a device exists. Fingerprinting tells you what kind of device it is. The hard part isn't asking the device — it's deciding how much to trust the answer. This page teaches the cascade method by letting you build identity verdicts with real evidence and watch the rules play out live.

▸ How is the verdict calculated?

Each evidence source has a confidence ceiling based on its class: SSDP 0.75 · RTSP 0.75 · HTTP realm 0.70 · HTTP Server token 0.70 · OUI 0.40 · hostname 0.20. The verdict's ceiling is the maximum among selected sources that agree on vendor. Independent classes are counted by category (SSDP / HTTP / RTSP / OUI / hostname). The chapter's admissibility threshold is three or more independent classes agreeing for vendor-family precision.

What "ceiling" means

A ceiling is the limit of what a clue can prove. Even if the clue looks convincing, you are not allowed to trust it beyond that level.

Example. If you see someone wearing Nike shoes, you can say: "They are wearing Nike shoes." You cannot say: "They work for Nike," "They are Michael Jordan," "They own Nike."

Same idea here. A MAC address starting with c0:56:e3 tells you the network card was made by Hikvision. It does not tell you the whole device is a Hikvision camera — a third-party device could use a Hikvision NIC. That's why OUI has a ceiling of 0.40. To trust the identity beyond that, you need other sources of evidence corroborating.

How to use this tab

  1. Pick a device on your network you want to identify — an IP camera, NVR, NAS, printer, or smart-home hub works best.
  2. Set TARGET to its IP address (Step 1 below).
  3. Run each probe in order — HTTP, RTSP, MAC, SSDP — in your terminal, and read what the device tells you.
  4. Apply the cascade. For each source, ask: which vendor does this indicate, and what's the confidence ceiling? Use the Practice tab to remind yourself of the rules.
  5. Look up the MAC OUI with the tool at the bottom — paste the MAC address and find the manufacturer instantly, no network calls.
Step 1 — Set your target

Pick an IP address on your network. Most home networks use 192.168.1.x or 10.0.0.x. Find your camera or NVR's IP from your router's admin page or DHCP lease list.

TARGET=192.168.1.50 # replace with your device's IP
Step 2 — HTTP banner & realm

What this gets you: the device's web server name (Server: header) and the login realm (WWW-Authenticate: header). The realm is usually the stronger of the two — it's firmware-baked.

curl -sI http://$TARGET/

What you'll see: a 401 Unauthorized response with headers like Server: DNVRS-Webs and WWW-Authenticate: Basic realm="Hikvision Digital Technology". The 401 is normal — you don't need credentials to read the banner.

Step 3 — RTSP banner (cameras only)

What this gets you: the camera's video-streaming protocol banner. Works on most IP cameras and DVRs. The banner is vendor-bearing even on a 401 response.

printf 'OPTIONS rtsp://%s/ RTSP/1.0\r\nCSeq: 1\r\n\r\n' "$TARGET" | nc -w 2 $TARGET 554

What you'll see: something like RTSP/1.0 401 Unauthorized with a Server: line naming the vendor (Hikvision, Dahua, Axis, etc.). If nc isn't installed, you can use openssl s_client or a Python one-liner with sockets.

Step 4 — MAC address (same network only)

What this gets you: the device's hardware MAC address. The first three bytes are the OUI — the manufacturer of the network chip.

arp -n $TARGET

What you'll see: something like 192.168.1.50 ether c0:56:e3:01:02:03. Take the first three octets (c0:56:e3) and paste them into the OUI lookup tool below.

Step 5 — SSDP / UPnP broadcast (same network only)

What this gets you: a structured manufacturer + model self-report. Strongest single identity source — when it works, it pins the model name, not just the vendor.

echo -e 'M-SEARCH * HTTP/1.1\r\nHOST:239.255.255.250:1900\r\nMAN:"ssdp:discover"\r\nMX:2\r\nST:ssdp:all\r\n\r\n' | nc -u -w 5 239.255.255.250 1900

What you'll see: a list of LOCATION: URLs. Fetch any of them with curl to read the device.xml — that file contains the manufacturer, model name, and friendly name in structured fields.

Free OUI lookup — find any MAC's manufacturer

Paste a MAC address or just the first three octets. Runs entirely in your browser — no network calls, nothing transmitted. Bundled database of about 250 common IoT, networking, camera, and consumer-electronics manufacturers.

Not in our local database? Try the full IEEE registry at wireshark.org/tools/oui-lookup.html or IEEE oui.txt.

Apply the cascade. For each source you collected, ask: which vendor does it indicate, and what is the confidence ceiling? Three or more independent classes agreeing makes the vendor claim admissible at family level. SSDP alone can pin the model. A MAC with a real IEEE-registered OUI corroborates. A locally-administered MAC is silent — not contradictory. A generic Server: Apache or aiohttp is the web server software, not the device identity. Beware any field labeled "firmware" that holds a transport-library version — that is the category error the chapter is built around.
Chapter 2 vocabulary · what these acronyms actually mean

Every term used in the playground and in the scan commands, defined in plain English. The cascade method is in part a vocabulary problem — knowing what each acronym is and is not is half the discipline.

Foundational concepts
Ceiling
the limit of what a clue can prove
A ceiling is the maximum confidence you are allowed to assign to a claim based on a given evidence source. Even if the clue looks convincing, you cannot trust it beyond that level. Example: seeing Nike shoes proves the person is wearing Nike shoes — it does not prove they work for Nike, they are Michael Jordan, or they own Nike. Same idea with network evidence: a Hikvision OUI proves the network card was made by Hikvision, not that the whole device is a Hikvision camera. To trust beyond the ceiling, corroborate with other independent sources.
Independent class
a kind of evidence, not a count of mentions
The cascade counts classes of evidence, not repetitions. SSDP, HTTP, RTSP, OUI are four different classes. Four mentions of the same banner from the same source is still one class. Admissibility requires at least three independent classes agreeing on vendor.
Admissibility
whether downstream tools can act on the claim
Whether the next stage of the pipeline is allowed to act on a finding. Decided per-host and per-precision. A device can be admissible at family (vendor-wide CVE checks are fine), conditional at model (model-specific checks need human review), and inadmissible at firmware (the firmware claim is a category error and cannot be trusted) — all at the same time.
Category error
right data, wrong field
A scanner puts a real, precise value into a field where it does not belong. Example from this lab: the API reports firmware_version: "3.13.5". That number is real — but it is the version of the Python web library running the simulator, not the camera's firmware. Real number, wrong field. Acting on a category error produces fabricated vulnerability matches downstream. The most dangerous identity mistake.
Identity sources (ranked by ceiling)
ONVIF
Open Network Video Interface Forum
An industry-standard API for IP cameras. Devices that support ONVIF expose a GetDeviceInformation call returning structured manufacturer, model, and firmware. The strongest possible identity signal — when it answers, the cascade is essentially done. Not every camera implements it.
ceiling: 0.85 (when present)
SSDP / UPnP
Simple Service Discovery Protocol / Universal Plug and Play
A network protocol that lets devices broadcast themselves on the local network. Devices respond with a URL pointing at a structured device.xml containing manufacturer, model, and friendly name. Used by Smart TVs, Sonos, Roku, IP cameras, printers. The single best identity surface short of ONVIF — structured, named fields, not free text.
ceiling: 0.75
RTSP
Real Time Streaming Protocol
The protocol IP cameras use to deliver video streams. Runs on TCP port 554 by default. Send an OPTIONS request and the camera responds with a vendor-bearing Server: header — even on a 401 Unauthorized. No credentials needed to read the banner.
ceiling: 0.75
HTTP realm
authentication realm string
When a web server requires authentication, it responds with 401 Unauthorized and a header like WWW-Authenticate: Basic realm="Hikvision Digital Technology". The realm string is firmware-baked — the device has to send it for the auth flow to work. Hard to anonymize.
ceiling: 0.70
HTTP Server token
the Server: header value
The Server: header in an HTTP response. Sometimes vendor-specific (Hikvision's DNVRS-Webs), sometimes generic (Apache, nginx, aiohttp). When generic, it identifies the web server software running on the device — not the device itself. Weaker than realm because operators or proxies can rewrite it.
ceiling: 0.70 (when vendor-specific) / 0.0 (when generic)
OUI
Organizationally Unique Identifier
A 24-bit number assigned by the IEEE Registration Authority to equipment manufacturers. It's the first three bytes of any MAC address — for example, c0:56:e3 is Hikvision Digital Technology's registered OUI. Every real piece of network hardware ships with an IEEE-assigned OUI burned into its network chip. The OUI identifies who made the network card; it doesn't always identify the whole device.
ceiling: 0.40
Hostname
container/operator-set name
A name attached to the device — typically set by the device owner or the container runtime. Useful as a prior but easy to set to anything, so the ceiling is low.
ceiling: 0.20
Networking basics
MAC address
Media Access Control · hardware address
A 48-bit hardware address attached to every network interface (Wi-Fi, Ethernet, etc.). Format: six hex pairs like c0:56:e3:00:00:01. First three bytes = OUI (the manufacturer). Last three = a serial chosen by the manufacturer. A locally-administered MAC (second-least-significant bit of the first byte set to 1) is a placeholder — not tied to any manufacturer. Detect it by checking if the second hex digit of the first byte is 2, 3, 6, 7, A, B, E, or F.
LAA
locally-administered address
A MAC address that was assigned by something local (Docker container runtime, virtualization platform, randomized Wi-Fi privacy, operator override) — not by the IEEE. OUI lookup yields no useful vendor. Treat this as a silent witness, not a contradiction. The other identity sources still carry the claim.
aiohttp
a Python web library
An async HTTP library for Python. Often shows up in the Server: header of devices whose web interface is written in Python. It tells you the device runs a Python web stack — nothing about the device itself. The lab's worked example of a category error: the scanner copies the aiohttp version into a firmware_version field and produces a false-confident value.
Downstream consumption
CPE
Common Platform Enumeration
A standardized naming format for software, operating systems, and hardware — used by vulnerability databases. Looks like cpe:2.3:a:hikvision:ip_camera:*:*:*:*:*:*:*:*. The a: means application; o: means operating system; h: means hardware. Choosing the right part is an admissibility decision in itself.
CVE
Common Vulnerabilities and Exposures
A publicly-published catalog of known software vulnerabilities, each with a unique identifier like CVE-2024-12345. Phase 3 of the security pipeline matches the device identity (via CPE) against the CVE database. A bad fingerprint upstream produces bad CVE matches downstream.
